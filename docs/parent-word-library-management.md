# 家长端单词库管理工具设计

## 目标

为家长提供一个低成本维护孩子英语单词学习内容的工具。第一版只保留一个单词库，家长通过手动录入、粘贴文本、拍照识别等方式新增单词，并在库内分为“新词”和“易错词”两大类。

这个工具的核心不是“存单词”，而是让家长持续、轻松、可控地维护孩子要学什么。

## 使用对象

- 家长：维护单词内容，整理新词和易错词。
- 孩子：不直接管理单词库，只接收学习任务。
- 系统：保存单词库数据，并为后续学习功能预留状态字段。

## MVP 范围

第一版只做家长端单词库管理，不做复杂的学习算法和详细报表。

必须包含：

- 一个固定单词库，不需要维护词库名称。
- 单词库内新增、编辑、删除单词。
- 单词库内按新词、易错词两大类管理。
- 手动逐个录入单词。
- 粘贴文本批量导入单词。
- 拍照识别导入单词。
- 单词按新词、易错词两大类管理。
- 标记单词学习状态：未学、学习中、需强化、已掌握。

暂不包含：

- 自动语音评分。
- AI 自动出题。
- 复杂遗忘曲线参数配置。
- 多家庭、多学校、多老师协作。

## 关键问题

### 1. 家长不是专业教研人员

界面不能要求家长理解太多教学术语。家长最常见的输入方式是：

- 学校教材。
- 老师发的单词表。
- 课外绘本或分级阅读。
- 家长自己整理的错词。

所以工具要优先支持“从一张表或一段文本快速变成可用单词库”。

### 2. 小学生背单词不只是英文和中文释义

一个单词最少需要：

- 英文单词。
- 中文释义。
- 发音。
- 例句。
- 是否属于新词或易错词。

但第一版不应强制每个字段都填。否则家长维护成本太高。

### 3. 单词库要服务后续学习闭环

如果只做列表增删改查，后面孩子端会缺少复习依据。单词库管理阶段至少要预留：

- 单词难度。
- 是否必背。
- 学习状态。
- 初次学习时间和复习策略由学习系统后续生成。

## 信息架构

家长端建议包含 2 个一级区域：

1. 单词库
2. 设置

第一版把“手动录入、粘贴导入、拍照导入”都放在单词库页，不再单独做导入一级导航。

## 页面设计

### 单词库总览页

用途：让家长管理唯一的单词库，并在新词、易错词之间快速切换。

核心内容：

- 单词数量。
- 新词数量。
- 易错词数量。
- 最近更新时间。

主要操作：

- 逐个录入。
- 粘贴导入。
- 拍照导入。

分类入口：

- 全部单词。
- 新词。
- 易错词。

### 单词库详情页

这是家长最常用的页面。

顶部信息：

- 单词数。
- 最近更新时间。

主要操作：

- 添加单词。
- 手动录入。
- 粘贴导入。
- 拍照导入。
- 批量修改分类。
- 导出。

单词表字段：

- 单词。
- 音标。
- 中文释义。
- 单词类型：新词、易错词。
- 例句。
- 难度。
- 是否必背。
- 学习状态：未学、学习中、需强化、已掌握。

批量操作：

- 批量设为新词。
- 批量设为易错词。
- 批量设置学习状态。
- 批量设置难度。
- 批量删除。

### 导出

导出不能直接生成固定文件，必须让家长先确认内容。

导出格式：

- 默写练习表，导出 Word，适合打印给孩子默写。

导出范围：

- 全部单词。
- 未学。
- 学习中。
- 需强化。
- 已掌握。

默写练习表字段：

- 序号。
- 中文。
- 英文默写区。

交互要求：

- 导出前展示预览表。
- 预览表里的中文可以临时编辑，但不反写正式单词库。
- 确认后导出 Word。

### 编辑与纠错

单词库必须支持后续编辑，因为拍照 OCR、手动录入、粘贴解析都可能产生错误。

可编辑内容：

- 不允许修改英文单词本身。
- 可修改单词属性：音标、中文释义、单词类型、例句、难度、是否必背、状态。
- 如果英文单词本身录错，家长需要删除后重新录入。

单词编辑入口：

- 单词表中点击某一行进入编辑。
- 单词表中直接行内编辑常用字段，例如中文释义、单词类型、难度。
- 批量选择后统一修改单词类型、难度、状态。

纠错场景：

- OCR 把英文识别错，例如 `climb` 识别为 `clirnb`。
- 中文释义漏字或错字。
- 一个单词被拆成两条记录。
- 两个单词被合并成一条记录。
- 重复导入了同一个单词。

编辑保存前的校验：

- 英文单词为空不能保存。
- 同一词库内疑似重复时提示家长。
- 已入库单词的英文单词字段不可编辑。

编辑后的处理：

- 普通字段修改，例如释义、例句、标签，不重置孩子学习进度。
- 合并重复词时，需要选择保留哪条单词记录，并把孩子进度合并到保留记录上。
- 草稿阶段删除单词行时，直接从草稿中移除。
- 已保存但状态为未学的单词删除时，直接物理删除。
- 学习中、需强化、已掌握的单词删除时，使用独立删除标记做逻辑删除，不改变历史学习记录。

建议保留修改记录：

- 谁修改的。
- 修改时间。
- 修改前内容。
- 修改后内容。
- 修改原因，可选。

第一版不一定要做完整版本回滚，但至少要能看到最近修改记录，方便排查“为什么孩子看到的单词变了”。

### 新增单词入口

单词库详情页里的“添加单词”不应该只有一个表单。建议点击后出现 3 种方式：

- 手动录入：适合临时补 1 到 5 个单词，例如孩子当天错词。
- 粘贴导入：适合老师发的文字版单词表。
- 拍照导入：适合纸质教材、纸质作业、班级群图片。

这 3 种方式最终都进入同一个“导入预览表”，由家长确认后再写入词库。

统一预览表必须显示：

- 单词。
- 中文释义。
- 音标。
- 单词类型：新词、易错词。
- 例句。
- 是否重复。
- 是否缺少必要信息。

### 手动录入页

手动录入要足够轻，不要做成复杂词典编辑器。

字段：

- 英文单词，必填。
- 中文释义，必填。
- 音标，可选。
- 单词类型，必填：新词、易错词。

交互建议：

- 保存后不关闭表单，方便连续录入。
- 支持回车保存并新增下一个。
- 单词类型默认选中新词。
- 如果从“错词整理”入口进入，单词类型默认选中易错词。
- 逐个录入时不展示状态字段。新词默认未学，易错词默认需强化。
- 输入英文单词时检查当前词库是否已存在。
- 如果单词已存在，提示“更新现有单词”或“仍然新增为同形词”。
- 保存后显示轻提示，不打断家长继续录入。

需要注意：

- 小学阶段会遇到同一个英文词有多个中文意思，不要简单地全局禁止重复。
- 重复判断第一版可以按同一词库内 `text + meaningZh` 判断，单纯 `text` 相同只提示，不强拦。
- “新词/易错词”是家长录入时对学习用途的判断，不等同于孩子端的真实掌握状态。孩子端仍然要用学习记录判断是否已经掌握。

### 粘贴导入页

第一版优先支持粘贴文本，不急着做复杂 Excel 解析。

支持格式：

```text
apple 苹果
banana 香蕉
read 阅读
```

也可以支持逗号和制表符：

```text
apple,苹果,An apple is red.
banana,香蕉,I like bananas.
```

导入流程：

1. 粘贴或上传内容。
2. 系统解析为预览表。
3. 家长修正错误行。
4. 选择导入为新词还是易错词。
5. 确认导入。

解析预览必须显示：

- 成功识别多少行。
- 有问题多少行。
- 重复多少个。
- 将要覆盖还是跳过重复词。

### 拍照导入页

拍照导入的目标不是“自动准确入库”，而是减少家长打字量。OCR 结果必须经过家长确认。

入口：

- 从相机拍照。
- 从相册选择图片。
- 从剪贴板粘贴图片，适合电脑端处理班级群截图。

拍照流程：

1. 家长拍照或选择图片。
2. 系统上传图片并执行 OCR。
3. 系统尝试拆分为单词、中文释义、例句。
4. 系统生成导入草稿，不写入正式单词库。
5. 展示草稿预览表。
6. 家长修正识别错误和缺失字段。
7. 家长删除不需要的行。
8. 系统检查重复词和低置信度字段。
9. 家长确认入库。
10. 系统把有效草稿行转换为正式单词。

识别预览必须包含：

- 原图缩略图。
- OCR 原始文本。
- 结构化后的单词列表。
- 低置信度标记。
- 重复词标记。
- 无法识别行。
- 每一行的处理状态：待确认、已修改、异常。

草稿预览表支持的操作：

- 直接编辑单词、中文释义、例句、类型。
- 删除某一行，直接从当前草稿中移除。
- 把无法识别的一行拆成多行。
- 把被错误拆开的多行合并为一行。
- 重新识别当前图片。
- 取消本次导入草稿。
- 确认入库。

确认入库前的校验：

- 英文单词为空的行不能入库。
- 中文释义为空的行可以入库，但要提示家长确认。
- 手动录入的草稿行必须包含英文单词和中文释义。
- 确认入库时按单词类型设置默认学习状态：新词为未学，易错词为需强化。
- 重复词默认跳过，也允许家长选择更新已有单词。
- 低置信度字段不阻塞入库，但要高亮提示。

入库后的结果反馈：

- 成功新增多少个单词。
- 跳过多少个重复词。
- 更新多少个已有单词。
- 仍有多少行未处理。
- 提供“查看本次导入结果”和“撤销本次导入”入口。

图片处理建议：

- 支持裁剪图片，只识别选中区域。
- 支持旋转图片。
- 支持重新识别。
- 保留原图一段时间，方便排查识别错误。

第一版可以接受的限制：

- 只支持中英文混合单词表，不支持复杂表格。
- 不承诺 100% 识别准确。
- 不直接从教材整页中推断完整课程结构。

需要警惕：

- 拍照导入看起来很有吸引力，但工程复杂度明显高于粘贴导入。
- 如果 OCR 做不好，家长会觉得“还不如自己打字”。因此第一版必须把修正体验做好，而不是追求自动化。
- 如果使用第三方 OCR，要注意孩子教材、作业图片可能涉及隐私，至少要在设置里说明图片处理方式。

## 交互原则

- 默认让家长少填字段，后续再补全。
- 粘贴导入和拍照导入必须有预览和撤销入口。
- 拍照识别结果不能直接入库，必须经过家长确认。
- 手动连续录入不能每次都打断家长。
- 未学单词删除时可以物理删除。
- 学习中、需强化、已掌握的单词删除使用独立删除标记，不占用学习状态。
- 单词重复时优先提示，不自动覆盖。

## 第一版推荐流程

1. 家长进入唯一的单词库。
2. 家长选择分类：新词或易错词。
3. 家长选择新增方式：手动录入、粘贴导入或拍照导入。
4. 系统解析并展示预览。
5. 家长修正少量错误。
6. 家长确认导入。
7. 家长继续维护新词和易错词。

## 非常容易被忽略的设计点

### 错词不应只存在于孩子端

家长会希望围绕错词做二次整理。建议支持“把孩子端错词加入易错词分类”，这会成为非常实用的功能。

### 词库不一定按教材组织

小学生的英语学习材料经常来自绘本、动画、课外班、老师临时单词表。不要把系统做成只能按教材版本组织。

### 家长最需要的是省事，不是功能多

第一版更应该把“粘贴导入、手动连续录入、重复词处理”做好，而不是做复杂标签体系。

### 拍照导入不能替代人工确认

家长拍照的图片质量不可控，可能有反光、倾斜、手写、表格线、教材插图。拍照导入的正确定位是“帮家长生成草稿”，不是“自动建好词库”。

### 要避免家长把系统当成惩罚工具

如果家长端只强调错词、错误率、排名，孩子会抗拒。建议措辞使用“需要再练”“已熟悉”，少用“错误”“失败”。

## 后续迭代

- 支持自动补全音标、发音、例句。
- 支持教材内置词库模板。
- 支持从孩子错词自动生成复习词库。
- 支持按遗忘曲线自动调整复习计划。
- 支持家长自定义奖励规则。
- 支持打印单词卡片。

## 第一版范围

第一版优先覆盖：

1. 单词新增、编辑、删除。
2. 手动连续录入。
3. 粘贴文本导入。
4. 拍照 OCR 导入草稿。
5. 导入预览和重复词处理。

第一版暂不覆盖：

- AI 自动生成完整词库。
- 复杂学习报表。
- 过细的教材版本管理。

原因是这些功能看起来高级，但在真实家庭场景里，最先卡住的是“家长能不能快速把今天老师发的单词放进去”。
